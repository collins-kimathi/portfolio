01 It started with a button that did nothing

I remember the exact moment. I had an HTML page, a button, and absolutely no idea how to make it do anything when clicked. Someone told me "just use JavaScript." Cool. What is JavaScript?

That question kicked off one of the best and most frustrating chapters of my life. I had no computer science background, no dev friends nearby, and a laptop that took two minutes to open VS Code. The playing field was not exactly stacked in my favour.

Reality Check

There is no clean starting line when you learn to code. You just pick a thing, start pulling threads, and eventually enough threads are in your hands that something starts to make sense.

02 Learning JavaScript — the foundation grind

I started with the basics. Variables. Data types. Conditionals. Loops. Functions. It sounds simple, and in isolation each concept is not that hard. The problem is they never live in isolation. Real code mixes them all together and expects you to keep up.

Early Collins — circa Week 2
// I was genuinely proud of this
let name = "Collins";
if (name === "Collins") {
  console.log("Hello, me!");
}
// It printed. I felt like a wizard.

The DOM was where things started to feel real. Selecting elements, listening for events, changing content dynamically — that was the first time I felt like I was building something rather than just writing text in a file.

  • Variables and scope — took two weeks to truly get let vs const vs var
  • Array methods — map, filter, reduce felt like dark magic until they didn't
  • Async JS — setTimeout, Promises, then async/await. Each one blew my mind
  • DOM manipulation — this was the dopamine hit that kept me going
  • Fetch API — first time I pulled live data into a page, I nearly fell off my chair

03 The dark valley (everyone goes through this)

About two months in, I hit a wall. I knew enough to know I did not know enough. Tutorials felt easy but my own projects felt impossible. I would watch a video, nod along, then open a blank file and freeze.

😬

I spent an entire Saturday trying to build a to-do list from scratch without a tutorial. I gave up at 11pm and watched Netflix instead. The next morning I tried again and finished it by lunch. That gap between giving up and trying again is where most of the learning actually lives.

The valley is a rite of passage. You are not stuck because you are bad at this. You are stuck because you are transitioning from consumer to creator — from following instructions to writing them. That is genuinely hard and it takes time.

⚠️ Tutorial Trap

There is a thing called tutorial hell. You watch tutorial after tutorial and feel productive, but you are not building real intuition. The only way out is to close the video and build something broken on your own. The broken version teaches you more than the tutorial ever could.

04 Entering the React dimension

I had been hearing about React for months before I tried it. "It is just JavaScript," people said. That is technically true and completely unhelpful as a description. React is JavaScript the way a Formula 1 car is just a vehicle.

The first thing that broke my brain was JSX — writing HTML inside JavaScript. It looked wrong. It felt wrong. My eyes kept rejecting it. But after a few days it started to feel natural, and then one day it felt inevitable.

My first React component — Week 1
function MovieCard({ title, year }) {
  return (
    <div className="card">
      <h2>{title}</h2>
      <p>{year}</p>
    </div>
  );
}
// It worked. I stared at it for a full minute.

Props made sense quickly. State took longer. The idea that a component could have its own memory, and that changing that memory would automatically update the UI — that felt like actual magic. Understanding useState was the moment React stopped feeling like a foreign language.

⚛️ React Concepts — In Order of "Oh So THAT'S What That Means"

Components → JSX → Props → useState → useEffect → component reuse → thinking in components → building Ciniverse and wondering why I ever used vanilla JS for anything bigger than a button.

05 The moment it all clicked

It was not a single dramatic moment. It was more like a slow dawn. One day I was adding a feature to a project and I realised I had not checked a tutorial in two hours. I was just writing code and it was doing what I expected. That quiet confidence is what "it clicked" actually feels like.

Building Ciniverse — my movie app — was the project that consolidated everything. I had to think about state management, component structure, API calls, conditional rendering, and UI polish all at once. The fact that it exists and works is the best proof that the journey was worth it.

✅ The Real Milestone

You know you have levelled up when you stop looking for tutorials and start looking for documentation. That shift — from needing to be guided to knowing how to find answers — is the actual graduation moment.

  • Component thinking changes how you see every interface, not just ones you build in React
  • State management is 60% of what makes or breaks a React app
  • useEffect is powerful and easy to misuse — respect it
  • The React docs are actually really good. Read them, not just videos
  • Building real projects is irreplaceable. Tutorials are just the warm-up

06 Every resource that actually helped

I went through a lot of things that did not help. Here are the things that did — honest ratings included.

W3Schools — JavaScript
Where I learned every fundamental concept. Copy-pasting examples until I understood why they worked was my whole strategy.
Great for fundamentals
JavaScript Mastery
Adrian's project-based tutorials are the reason I could build real things. His Ciniverse-style projects directly shaped how I approached my own movie app.
Top tier for projects

The new React docs (react.dev) are interactive, clear, and honest about what is hard. Once you have basics down, this is your best friend.
Essential reference

The source of truth for how JavaScript actually works. Intimidating at first, invaluable forever. Every professional I know keeps this tabbed.
Authoritative reference

Short, focused video series on specific topics. His async JavaScript and React hooks series helped me fill specific gaps without sitting through hours of context.
Great for filling gaps

Beginner friendly

07 What I would tell myself on day one

If I could go back and leave a note for the version of me who did not know what JavaScript was, here is what it would say.

  • Confusion is not a sign you are doing it wrong. It is the sensation of your brain building new structure. Stay in it.
  • Build things before you feel ready. The only way to feel ready is to have built things already — it is a paradox you have to cheat your way through.
  • Pick one resource at a time. Resource-hopping is just a more productive-feeling version of procrastinating.
  • Your first projects will be terrible. Ship them anyway. The habit of finishing matters more than the quality right now.
  • Console.log everything. No shame. Every developer does this. Every single one.
  • React will not make sense until it does. Do not try to force it. Keep building small things and one day the model in your head will snap into place.
💛

The journey from zero to feeling competent is not a straight line, and no one finishes it. There is always more to learn. But there is a point where the fear of the blank file goes away and gets replaced by curiosity. Getting to that point is worth everything it costs to get there.
